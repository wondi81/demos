      개발 적용 가이드

      프론트엔드 개발자 한 분이 그대로 옮겨 쓸 수 있게, Figma 변수와 같은 이름의 CSS 변수와 JSON을 함께 드립니다.

      1. 토큰 → CSS 변수

      /* Figma  color/bg/surface  →  CSS */
:root {
  --color-bg-surface: var(--gray-0);
  --color-text-muted: var(--gray-600);
  --space-4: 16px;
  --radius-md: 8px;
}
[data-theme="dark"] {
  --color-bg-surface: var(--gray-900);
  --color-text-muted: var(--gray-300);
}

/* 컴포넌트는 semantic만 참조 */
.card {
  background: var(--color-bg-surface);
  padding: var(--space-4);
  border-radius: var(--radius-lg);
}

      같은 값을 tokens.json(W3C Design Tokens 형식)으로도 내보내 Tailwind 설정이나 다른 프레임워크에 연결할 수 있게 합니다.

      2. 반응형 기준

      이름범위열 · 여백규칙
      mobile0~7674열 · 16한 단, 하단 고정 버튼, 목록 → 상세 이동
      tablet768~10238열 · 24목록·상세 2단, 보조 패널은 접기
      desktop1024~127912열 · 32교사 화면 목록 300 고정 + 상세 가변
      wide1280~12열 · 최대 1280본문 최대 폭 고정, 여백만 늘어남

      버튼·입력은 모바일에서 최소 높이 44px(size=lg)를 씁니다. 글자 크기는 줄이지 않고 줄 수와 배치만 바꿉니다.

      3. 컴포넌트 사용 규칙

      이렇게

      한 화면에 primary 버튼은 하나. 나머지 행동은 secondary·ghost로 내립니다.

      이렇게 하지 않기

      primary가 둘이면 교사가 어떤 버튼이 최종 행동인지 망설입니다.

      이렇게
      background: var(--color-bg-danger-subtle)

      색은 semantic 토큰 이름으로만 지정합니다. 다크 모드와 BI 교체가 자동으로 따라옵니다.

      이렇게 하지 않기
      background: #fdeeec

      HEX를 직접 쓰면 다크 모드에서 흰 상자가 뜨고, 색을 바꿀 때 파일마다 찾아 고쳐야 합니다.

      이렇게
      점수는 0~25 사이로 입력해 주세요.

      오류는 입력칸 바로 아래에 이유와 고칠 방법을 함께 적습니다. 색만으로 알리지 않고 아이콘을 붙입니다.

      이렇게 하지 않기
      입력 오류

      빨간 테두리와 "오류"만 띄우면 무엇을 고쳐야 할지 알 수 없습니다.
