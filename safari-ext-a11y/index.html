크롬 확장을 사파리로 옮길 때 막히는 곳

강의 중 정해진 시각에 알림을 띄우고 대체자료를 맞춰 주는 시각장애인 보조 확장을 가정했습니다. 권한별 사파리 지원 여부와, 알림이 스크린리더에 어떻게 전달되는지 직접 확인해 보세요.

1. manifest 호환성 점검기

크롬 MV3 manifest.json 예시입니다. 수정해서 다시 점검해 볼 수 있습니다.

권한·API별 크롬, 사파리 macOS, 사파리 iOS 지원 현황
권한·APIChromeSafari macOSSafari iOS판정메모

출처: MDN browser-compat-data (가져온 날짜 2026-11-02). 지원 버전은 해당 버전 이상을 뜻합니다.

2. 강의 알림 접근성 미리보기

재생하면 강의 시간이 1초에 1분씩 흐릅니다. 같은 알림이 보완 전과 보완 후에 동시에 뜹니다.

강의 화면 (가상)
00:00 / 00:25

    보완 전 접근성 없음

    대기 중

    색만 바뀌는 div입니다. 역할·읽어주기 속성이 없어 스크린리더는 읽지 않고, 글자 대비도 :1입니다.

    보완 후 접근성 적용

    알림이 오면 이 창이 즉시 읽히고, 글자 대비는 :1입니다.

    보완한 내용

    • 스크린리더가 읽음 role="alert" 영역에 문구를 넣어 즉시 안내
    • 키보드로 다시 듣기 Alt+R로 마지막 알림 반복
    • 포커스 이동 선택 시 알림 창으로 포커스 이동, 닫으면 원래 자리로 복귀
    • 대비 4.5:1 이상 글자와 배경 색 대비를 계산해 확인
    • 글자 크기 200%까지 깨지지 않음 크게 보기에서도 줄바꿈으로 수용

    3. 작업 순서와 완료 기준

    1. 코드 분석크롬 전용 API·권한·백그라운드 구조를 목록으로 정리하고, 사파리 지원 여부를 표로 확정한다.
    2. 문제 보완미지원 API를 대체 구조로 바꾼 뒤 macOS·iOS 빌드에서 알림이 정해진 시각에 동작하면 끝.
    3. 접근성 보완 (VoiceOver 실기기 점검)알림 읽힘·키보드 조작·포커스 이동이 실기기에서 모두 확인되면 끝.
    4. TestFlight 배포·테스트테스트 빌드로 실제 기기 시나리오를 통과하고 발견 항목이 정리되면 끝.
    5. App Store 심사 요청메타데이터·심사 메모를 갖춰 제출하고, 반려되면 수정 후 재제출까지 마치면 끝.
